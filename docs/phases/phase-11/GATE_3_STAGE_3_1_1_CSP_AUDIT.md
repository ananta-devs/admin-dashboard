## 1. Directive Breakdown & Enforcement

The Content Security Policy (CSP) generated by Next.js 16 request interceptor (`frontend/src/proxy.ts`) enforces the following complete directive set:

```http
default-src 'self';
script-src 'self' 'nonce-<NONCE>' 'strict-dynamic';
style-src 'self' 'nonce-<NONCE>';
style-src-attr 'unsafe-inline';
img-src 'self' blob: data:;
font-src 'self';
object-src 'none';
base-uri 'self';
form-action 'self';
frame-ancestors 'none';
connect-src 'self'
```

### 1.1 Nonce Entropy & Generation
- **Implementation:** `Buffer.from(crypto.getRandomValues(new Uint8Array(16))).toString("base64")`
- **Specification:** Uses standard Web Crypto CSPRNG (`crypto.getRandomValues`) generating 16 bytes (128 bits) of entropy, formatted as standard Base64 resulting in a 24-character string ending with padding (`==` or `=`).
- **Uniqueness:** Verified across sequential live HTTP requests on `http://localhost:3000`. Every request produces an unrepeatable, unpredictable cryptographic token.
- **Propagation:** The nonce is set in both the `Content-Security-Policy` HTTP header and passed down through the Next.js internal header `x-nonce`. The root layout (`frontend/src/app/layout.tsx`) binds this nonce to all Next.js hydration scripts, style bundles, and inline theme detection scripts.

## 2. Hardening Adjustments from Stage 3.1

### 2.1 Elimination of Dev Server Origins from `connect-src`
In Stage 3.1, `connect-src` contained:
```text
connect-src 'self' http://localhost:8000 ws://localhost:8000
```
This presented a critical security finding:
1. In a production environment, allowing client connections to loopback interfaces (`localhost:8000`) creates potential attack vectors for SSRF/CSRF and assumes the backend is directly reachable from the user agent's machine.
2. In VIBE's architecture, all client-side API requests use relative paths (`/api/v1/*`), which are proxied on the server by Next.js rewrites to `BACKEND_INTERNAL_URL`.

**Stage 3.1.1 Remediation:**
`connect-src` was strictly updated to:
```text
connect-src 'self'
```
Relative requests resolve to the same origin (`'self'`), satisfying CSP without allowing arbitrary external or loopback egress.

### 2.2 Re-examination of `style-src-attr 'unsafe-inline'`
An exhaustive technical audit was conducted to determine if `style-src-attr 'unsafe-inline'` could be safely removed.

**Empirical Findings:**
1. **Virtual Grid (`@tanstack/react-virtual`):** The spreadsheet subsystem (`frontend/src/components/spreadsheet/virtual-grid.tsx`) renders grids of up to 50,000 rows. Virtualization calculates dynamic row transforms and heights:
   ```tsx
   style={{
     position: 'absolute',
     top: 0,
     left: 0,
     width: '100%',
     transform: `translateY(${virtualRow.start}px)`
   }}
   ```
   Removing `style-src-attr 'unsafe-inline'` causes the browser to block inline style attributes. As a result, all 50,000 rows render stacked at `translateY(0px)`, crashing spreadsheet functionality.
2. **Dynamic UI Indicators:** Progress bars, custom KPI status widths (`style={{ width: `${pct}%` }}`), and layout drawer transforms rely on runtime calculated percentages.
3. **Apache ECharts:** ECharts renders dynamic canvas and SVG wrappers with inline styles.

**Risk Assessment & Justification:**
`style-src-attr 'unsafe-inline'` applies **only** to the HTML `style="..."` attribute, **not** to `<style>` elements. `<style>` elements remain protected by `style-src 'self' 'nonce-<NONCE>'`. Modern browsers do not execute JavaScript from CSS properties (expression/behavior are deprecated and unsupported in modern rendering engines). Therefore, retaining `style-src-attr 'unsafe-inline'` is an accepted, necessary industry standard pattern for virtualized DOMs while maintaining defense-in-depth against XSS.

## 3. Chrome DevTools MCP Audit & Console Verification

The application was loaded in Chrome via Chrome DevTools MCP at `http://localhost:3000`.

- **CSP Violations:** 0 CSP violation reports or blocked resource notices.
- **Script Execution:** Next.js hydration, React 19 tree mount, command palette (`Ctrl+K`), theme switching, and client-side page routing executed without CSP interference.
- **Resource Loading:** All SVGs, fonts, and stylesheets loaded strictly under `default-src 'self'`, `font-src 'self'`, and `img-src 'self' blob: data:`.
